Local-first ledger: ingestion, review and data integrity

A Python, React and SQLite application that stages heterogeneous records for review, preserves user decisions and exposes data-quality gaps. This case study contains no personal financial data.

Synthetic demo

private financial data stays local

What I built

  • A local Python backend and React interface with SQLite storage, document staging, review queues, transfer reconciliation and record provenance.
  • Human confirmation and undo for ambiguous matches, with saved decisions protected from automatic refreshes.
  • Synthetic-data demo generation, verified-backup and restore tooling, integrity checks and a loopback-only application boundary.

How it was checked

  • Reviewed the architecture, synthetic-demo procedure and dated verification records; no personal source records were opened for this showcase.
  • The project provides a scratch-database smoke flow and a combined verification script covering tests, health, backup restoration and decision locks. These are existing procedures, not a new verification run in this review.

Not claimed

  • No real account details, balances, transaction amounts, correspondents, private messages or screenshots of personal records are shared.
  • No financial-advice capability, automated money movement, complete reconciliation or universal statement coverage is claimed.
  • This is a personal local application developed with coding-agent assistance, not a public SaaS product or a scale benchmark.
